# AGENTS.md

## Project Shape

- `football_scraper.py` contains the application: BBC match/table parsing, the interactive terminal UI, Now Playing, and stream search.
- `test_all_leagues.py` is a live BBC smoke test, not an isolated unit-test suite.
- `debug_*.py` and `extract_*.py` are investigation scripts. Keep production fixes in `football_scraper.py` unless a reusable test is being added.
- `footyres.sh` and `footyres.bat` are user-facing launchers. Keep their flags aligned with the Python CLI and README.

## Environment

Use Python 3.14 and the repository virtual environment:

```bash
source venv/bin/activate
python -m pip install -r requirements.txt
```

The app may install missing runtime packages itself, but development and tests should start from an installed environment. Set `PYTHONDONTWRITEBYTECODE=1` for checks so generated bytecode does not enter the worktree.

## Working Rules

- Treat BBC Sport as the source of truth for fixtures, scores, incidents, team names, and standings.
- Preserve graceful failure when BBC is unavailable or its schema changes. Report unavailable data instead of inventing fallback results or tables.
- Parse structured data from BBC's embedded `window.__INITIAL_DATA__` before relying on HTML/text fallbacks.
- Expect partial and nullable BBC payload fields. A malformed event, component, lineup, or card entry should be skipped without terminating the interactive session.
- Keep league display names and URL metadata centralized in `FootballScraper.leagues`.
- Keep network calls bounded by timeouts. Now Playing refreshes should fetch independent match details concurrently and should not extend the advertised cadence by a full collection cycle.
- Preserve existing terminal color helpers and interaction patterns. Verify output for zero scores, half-time, stoppage-time minutes, missing details, and narrow terminal wrapping when changing displays.
- Make the smallest correct change in the monolithic module; avoid broad extraction or cleanup unrelated to the requested behavior.
- Update `README.md` when user-visible flags, navigation, supported leagues, output, requirements, or launch behavior changes.

## Validation

Run checks from the repository root. Network-backed checks can vary with the day's schedule, so assert schemas and invariants rather than fixed match counts or club lists.

```bash
PYTHONDONTWRITEBYTECODE=1 python -m ruff check .
PYTHONDONTWRITEBYTECODE=1 python test_all_leagues.py
PYTHONDONTWRITEBYTECODE=1 python -m py_compile football_scraper.py
git diff --check
```

For parser changes, also add or run a focused synthetic payload check that covers the changed BBC shape without requiring a live match. For table, fixture, or card-detail changes, perform one live BBC smoke test when network access is available and state clearly when it is not.

`pyrightconfig.json` currently disables type checking; do not claim type-check coverage unless that configuration changes. Ruff ignores are documented in `ruff.toml`; do not expand them to hide new issues.

## Completion

Before handing off a change, confirm every modified user path starts, network failures remain non-fatal, no fabricated football data was introduced, generated `__pycache__`/`*.pyc` files are absent, and the relevant README text matches actual terminal output.
